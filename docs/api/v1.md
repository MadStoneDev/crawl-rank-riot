# RankRiot Jobs API — v1

The public, API-key-authenticated interface to RankRiot's crawler. A **job** is
a scan: you create one, poll it, then read its scored report and issues. It runs
the exact same pipeline as the RankRiot app, so results match the dashboard.

This document is the contract Vanward builds against. Recorded example responses
live next to it in [`samples/`](./samples/) and are generated from the real
scoring + serializer code (`crawl-rank-riot/src/scripts/generate-v1-samples.ts`).

- **Base URL:** `https://<crawler-host>/api/v1`
- **Status:** the surface and schemas below are implemented and the backing
  migration is applied. Provisioning of API keys is operator-side until the
  key-management UI ships (see [Provisioning](#provisioning)).

---

## Versioning

Every response carries two versions:

```json
{ "api_version": "v1", "schema_version": "1.1.0", "data": { ... } }
```

- `api_version` — the URL/surface version. Only changes for a breaking redesign.
- `schema_version` — semver of the response bodies. Minor bumps are additive and
  backwards-compatible (new fields); a major bump is a breaking shape change.

Assert `api_version === "v1"` and that `schema_version` is a major you support.

**Current: `1.1.0`.** 1.1.0 is additive over 1.0.0: projects, job `scope` +
`modules` + `external_ref` + `metadata`, and the per-job pages endpoints. Every
1.0.0 field is unchanged.

## Authentication

Send your key in **either** header:

```
Authorization: Bearer rrk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
X-API-Key: rrk_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Keys look like `rrk_<env>_<random>`. Only a SHA-256 hash is stored server-side,
so a key is shown **once** at creation — store it securely; it cannot be
recovered. A key belongs to a RankRiot user and can only act on that user's
projects.

### Scopes

| Scope | Grants |
|-------|--------|
| `jobs:read`  | list/read jobs, reports, issues, pages, usage |
| `jobs:write` | create and cancel jobs |
| `projects:read`  | list/read projects |
| `projects:write` | create projects |

A request missing the required scope gets `403 insufficient_scope`.

### Public endpoints (no key)

- `GET /api/v1/health` — liveness.
- `GET /api/v1/meta` — versions, scopes and the endpoint list, for discovery.

---

## Rate limits & usage

- **Per-key rate limit:** each key has its own requests-per-minute limit
  (default 60). Over it → `429 rate_limited`. `RateLimit-*` response headers
  report the window.
- **Monthly job quota:** a key may have an optional monthly cap on *jobs
  created*. Over it, `POST /jobs` returns `429 quota_exceeded`.
- **Metering:** every authenticated request and every created job is counted per
  key, per UTC day. `GET /api/v1/usage` returns month-to-date totals and the
  remaining quota. See [`samples/usage.json`](./samples/usage.json).

## Issue categories, severity & the speed tag

Each issue and each report deduction is classified consistently, and the API
exposes it in a display-ready form so Vanward needs no mapping of its own.

- **`category`** — one of `technical`, `content`, `media`, `aeo`. This is
  RankRiot's single source of truth for grouping (the crawler's score category).
  `category_label` is the display label: `Technical` / `Content` / `Media` /
  `AEO`.
- **`severity`** — `critical` | `high` | `medium` | `low`, taken from the
  issue's stored severity (the single source of truth; not re-derived).
- **`is_speed`** — a cross-category **speed** tag. Load performance spans two
  categories (page performance is `technical`, image performance is `media`), so
  there is no single "speed" category; `is_speed: true` marks the issues that
  are about load performance (`slow_page`, `slow_server_response`,
  `large_page_size`, `oversized_images`, `non_modern_image_format`,
  `missing_image_dimensions`). Use it to offer a "Speed" view that draws from
  both categories.

A report's `categories[]` gives the four category health **scores** (0–100) and
a separate **pass_rate** (0–100) — two distinct axes; display them separately.

## Attribution (`external_ref` + `metadata`)

Jobs and projects accept two optional attribution fields, echoed back on every
read:

- **`external_ref`** — your own identifier (string) for cross-referencing. Jobs
  and projects can be **filtered** by it on their list endpoints
  (`?external_ref=...`).
- **`metadata`** — a small JSON object stored and returned verbatim.

---

## Projects

A **project** is a site you scan. It is owned by the API key's user; jobs
reference a `project_id`. Create dedupes by normalised domain per owner, so
POSTing the same domain twice returns the existing project.

### Create — `POST /api/v1/projects`

Scope: `projects:write`.

```json
{ "domain": "acme.test", "name": "Acme Bookkeeping",
  "external_ref": "crm-42", "metadata": { "team": "growth" } }
```

- `domain` (or `url`) — the site. **One is required.** Normalised to a bare
  domain (scheme/`www`/path stripped) and stored as `https://<domain>/`.
- `name` — **required.**
- `external_ref`, `metadata` — optional attribution.

Returns `201 Created` with the project, or `200 OK` with the existing project if
that owner already has one for the domain (its attribution is updated). See
[`samples/project.json`](./samples/project.json). Errors: `400 validation_error`.

### List — `GET /api/v1/projects`

Scope: `projects:read`. Query: `limit` (1–100, default 25), `offset`,
`external_ref` (filter). Returns the owner's projects, most recent first.

### Get — `GET /api/v1/projects/:id`

Scope: `projects:read`. One project owned by the key's user, else
`404 project_not_found`.

## Modules & scope

Two optional `POST /jobs` fields control **how much** a job does.

**`scope`** bounds the crawl:

| `scope` | Crawls |
|---------|--------|
| `site` (default) | the whole site, as today |
| `page` | exactly one URL (the project home, or a `url` you pass) — no discovery |
| `urls` | an explicit `urls` list (max 50), no discovery beyond them |

For `page`/`urls`, every URL must be on the project's own domain.

**`modules`** selects which stages run. Omit it for the **full pipeline as
today** (crawl, store, issues, scoring). Pass an array to run only what you
need:

| module | what it does |
|--------|--------------|
| `fetch_extract` | crawl + extract per-page data (always implied — the base) |
| `tech_fingerprint` | detect platform/CMS, analytics, booking, CRM/chat, payment and email tools, frameworks and libraries, from the page's real loaded assets |
| `business_info` | NAP (name/phone/email/address), opening hours, service areas and social profiles, from JSON-LD + contact links + socials |
| `issue_detection` | run the SEO/AEO issue checks |
| `scoring` | compute the scored report (needs `issue_detection` for full deductions) |

A job that omits `scoring` is a pure **extraction** job: it writes no scored
report (so `GET /report` returns `404 report_not_ready`), no trend point, and
does not reschedule the project. `tech_fingerprint`/`business_info` output
appears per page under each page's `modules` (see [Pages](#pages)), and the
site-level `tech_fingerprint` rollup appears on the job's `result`.

## Jobs

### Create a job — `POST /api/v1/jobs`

Scope: `jobs:write`.

```json
{
  "type": "seo",
  "project_id": "9c8b7a65-4321-4a1b-8c7d-6e5f4a3b2c1d",
  "scope": "page",
  "url": "https://acme.test/contact",
  "modules": ["fetch_extract", "tech_fingerprint", "business_info"],
  "external_ref": "crm-42",
  "metadata": { "campaign": "q4-audit" },
  "options": { "maxPages": 500, "maxDepth": 5 }
}
```

- `type` — `"seo"` (default, full crawl) or `"audit"` (shallow).
- `project_id` — a project owned by the key's user. **Required.**
- `scope` — `"site"` (default) | `"page"` | `"urls"` (see
  [Modules & scope](#modules--scope)). `page` reads an optional `url`; `urls`
  reads a `urls` array (max 50). All page/urls URLs must be on the project's
  domain.
- `modules` — optional array selecting stages; omit for the full pipeline.
- `external_ref`, `metadata` — optional attribution.
- `options` — optional crawl overrides; clamped server-side to safe ranges
  (`maxPages` 1–100000 for seo / 1–500 for audit, `maxDepth` 1–10 / 1–5,
  `concurrentRequests` 1–10, `timeout`). For `page`/`urls` the crawl bounds are
  set by the scope. Unknown fields are ignored.

Returns `202 Accepted` with the job (status `running`). The scan runs
asynchronously; poll the job. See [`samples/job.json`](./samples/job.json) and
the page-scope [`samples/job_page_scope.json`](./samples/job_page_scope.json).

Errors: `400 validation_error` (no project_id, bad modules, off-domain URL),
`403 forbidden` (not your project), `404 project_not_found`,
`409 scan_in_progress` (one already running for that project),
`429 quota_exceeded`.

### Get a job — `GET /api/v1/jobs/:id`

Scope: `jobs:read`. Returns the job with its current `status` and `stats`.

```json
{
  "object": "job",
  "id": "3f1c9a2e-…",
  "type": "seo",
  "status": "completed",
  "project_id": "9c8b7a65-…",
  "created_at": "2026-10-22T09:00:00.000Z",
  "started_at": "2026-10-22T09:00:01.000Z",
  "completed_at": "2026-10-22T09:03:12.000Z",
  "stats": { "pages_scanned": 3, "links_scanned": 48, "issues_found": 5 },
  "failure_reason": null,
  "links": {
    "self": "/api/v1/jobs/3f1c9a2e-…",
    "report": "/api/v1/jobs/3f1c9a2e-…/report",
    "issues": "/api/v1/jobs/3f1c9a2e-…/issues"
  }
}
```

**Status lifecycle:** `queued` → `running` → `completed` | `failed` |
`cancelled`. Poll `GET /jobs/:id` until the status is terminal (a few seconds
between polls is plenty).

### List jobs — `GET /api/v1/jobs`

Scope: `jobs:read`. Query: `limit` (1–100, default 25), `offset`. Returns the
calling key's jobs, most recent first.

### Report — `GET /api/v1/jobs/:id/report`

Scope: `jobs:read`. The scored report for a completed job. `404 report_not_ready`
while the scan is still running. See [`samples/report.json`](./samples/report.json).

### Issues — `GET /api/v1/jobs/:id/issues`

Scope: `jobs:read`. Query: `limit` (1–200, default 50), `offset`. Open issues
for the job, each with `category`, `category_label`, `severity`, `is_speed`,
`page_url` (null for site-level issues) and `description`. See
[`samples/issues.json`](./samples/issues.json).

```json
{ "object": "list", "job_id": "…", "items": [ … ],
  "page": { "limit": 50, "offset": 0, "total": 5, "has_more": false } }
```

### Pages — `GET /api/v1/jobs/:id/pages`

Scope: `jobs:read`. Query: `limit` (1–200, default 50), `offset`. The per-page
extracted data for the job's crawl — a self-contained snapshot taken at scan
time (so it reflects *this* job, not a later re-scan). Each list item is
compact:

```json
{ "object": "list", "job_id": "…",
  "items": [ { "object": "page", "id": "…", "url": "https://acme.test/contact",
               "http_status": 200, "title": "Contact — Acme", "word_count": 180,
               "modules": { "tech_fingerprint": { … }, "business_info": { … } } } ],
  "page": { "limit": 50, "offset": 0, "total": 1, "has_more": false } }
```

See [`samples/pages.json`](./samples/pages.json). `modules` is populated only
for the modules the job ran.

### Page detail — `GET /api/v1/jobs/:id/pages/:pageId`

Scope: `jobs:read`. One page's **full** extracted data: `url`, `http_status`,
`title`, `meta_description`, `canonical_url`, `is_indexable`, `word_count`,
`content_length`, `headings` (h1–h6), `schema_types`, `structured_data` (parsed
JSON-LD blocks), `open_graph`, `twitter_card`, `images`, `internal_links`,
`external_links`, `detected_platform`, `scan_method`, plus `modules`.

The cleaned main **text** is omitted by default (it can be large). Request it
with `?include=content` to add a `content` field. See
[`samples/page.json`](./samples/page.json). `:pageId` is the page `id` from the
pages list. Errors: `404 page_not_found`.

### Cancel — `POST /api/v1/jobs/:id/cancel`

Scope: `jobs:write`. Requests cancellation of a running job and returns the job
(status `cancelled`). No-op if already finished.

## Usage — `GET /api/v1/usage`

Scope: `jobs:read`. Month-to-date usage for the calling key.

```json
{ "object": "usage", "period": "month", "period_start": "2026-10-01",
  "requests": 1284, "jobs_created": 37, "quota": 500, "quota_remaining": 463 }
```

## Errors

Errors use the same versioned envelope with an `error` object instead of `data`:

```json
{ "api_version": "v1", "schema_version": "1.1.0",
  "error": { "code": "insufficient_scope",
             "message": "This API key is missing the required scope 'jobs:write'.",
             "details": { "required_scope": "jobs:write", "scopes": ["jobs:read"] } } }
```

| HTTP | `code` | Meaning |
|------|--------|---------|
| 400 | `validation_error` | Missing/invalid request fields. |
| 401 | `invalid_api_key` | Missing or unrecognised key. |
| 401 | `key_revoked` | The key has been revoked. |
| 403 | `insufficient_scope` | Key lacks the required scope. |
| 403 | `forbidden` | Key's owner doesn't own the target project. |
| 404 | `project_not_found` / `job_not_found` / `page_not_found` / `report_not_ready` | Not found / not ready. |
| 409 | `scan_in_progress` | A scan is already running for that project. |
| 429 | `rate_limited` / `quota_exceeded` | Per-minute rate or monthly job quota hit. |
| 500 | `internal_error` / `database_error` / `auth_error` | Server-side failure. |

## Provisioning

Until the key-management UI ships, an operator provisions a key out of band with
the CLI (`crawl-rank-riot/src/scripts/api-key.ts`), run against the production
environment:

```bash
npm run apikey -- create --user <uuid> \
  --scopes jobs:read,jobs:write,projects:read,projects:write \
  --label "Vanward prod" --rate 60 --quota 500 --env live
npm run apikey -- list
npm run apikey -- revoke --id <key-uuid>
```

`create` prints the raw `rrk_live_…` key **once** — only its SHA-256 hash and
non-secret prefix are stored, so it cannot be recovered; hand it to the
integrator at that moment. See [`smoke.md`](./smoke.md) for a full mint → scan →
revoke walkthrough.

## Notes & limits

- The crawler runs as a single process today, so the rate limiter is in-memory
  (per instance) and cancellation is in-process. A distributed store is future
  work if the crawler scales out.
- One scan runs per project at a time (`409 scan_in_progress`).
- `schema_version` is `1.1.0`; `deduction.penalty` is a raw weighted-model float.
- A `page`/`urls` job only crawls the given URL(s); `urls` is capped at 50 and
  all URLs must be on the project's domain.
- The per-job pages snapshot is written for every job and stores the cleaned
  main text truncated to 100,000 characters.
